# Rams review lens — SOKOGEN Planner

## What this is (and isn't)

Rams' principles are a lens for finding waste, dishonesty and missing detail.
They are NOT the planner's identity. The identity lives in the design brief:
function is the floor, and on top sits SOKOGEN character — interesting and
interactive, led by bold typography, supported by depth, with small hidden
details that reward use.

So: Rams cuts what doesn't earn its place. SOKOGEN decides what does.

### Never flag these as excess (deliberate brand choices)
- Racing Sans One headers and bold typographic hierarchy
- Texture and depth that support hierarchy
- The breathing orb and the phone breathe intro (tap to skip)
- The subtle pop when a task is completed
- Small hidden details that reward use

If any of these is genuinely hurting a task (slowing capture, hurting
readability, causing layout jumps), say so — but critique the execution,
not the existence.

### Authority order
North Star (what it does) > design brief (how it looks and feels) > this lens.

## The ten principles, as questions for this planner

1. **Innovative** — Does new tech (sync, parsing, AI sorting) make a real job easier, or is it a gimmick?
2. **Useful** — Is the core path (capture, see Today, check off) the fastest, clearest thing on screen?
3. **Aesthetic** — Are spacing, type and color all from the tokens? Anything arbitrary?
4. **Understandable** — Is every control obvious without explanation? Do states say what happened?
5. **Unobtrusive** — Does anything pull focus that isn't the task? (Brand moments above are exempt.)
6. **Honest** — Does status (sync dot, counts, guesses) show the real state? No fake progress.
7. **Long-lasting** — Is this a durable pattern or a trend that'll date fast?
8. **Thorough** — Are empty, loading, offline, error, long-title and many-items states all designed? Do inputs keep text on blur, Enter, Escape and phone swipe-away?
9. **Efficient** — Small payloads, few requests, no wasted battery, no attention noise.
10. **As little as possible** — What can be deleted without losing information or SOKOGEN character?

## Process

1. State the core job of the screen or component first.
2. Rate only the principles that apply: Strong / Adequate / Weak. Skip the rest.
3. Check honesty (6), understandability (4) and thoroughness (8) first — they matter most here.
4. Name the top 2–3 problems, each with one concrete change and the exact file it would touch (use the file map in CLAUDE.md).
5. Name what to keep.
6. End with the one highest-leverage edit (often a deletion, but never a brand moment listed above).

## Rules

- Don't open a browser, take screenshots or start a server unless Cy asks.
